# 08. 팀원과 공유·협의할 사항

> 이 문서는 **다른 파트(앱, 영상, 하드웨어)와 맞춰야 하는 것**을 모았습니다. 합의된 내용은 §7에 날짜와 함께 기록합니다.
> **11/06~11/07에 앱 연동 방식이 합의되어 [12 협약안 v0.5](12_TEAM_AGREEMENT_V05.md)로 정리했습니다.** 11/03 초안의 HTTPS 전송, 클립 업로드, 오경보 버튼은 폐기되었고 §2에 달라진 점을 남겼습니다. 파트 이름은 역할로 적었습니다.

## 1. 지금 상태 (한 장 요약, 2026-11-08)

- 음성 파트는 **마이크(reSpeaker)와 파이5 도착 전**입니다 (마이크 11/11~11/18 예정, 파이5 일정 미정).
- **위급 감지 방식을 소리 분류에서 단어 인식(말소리를 글자로 바꿔 위급 단어를 찾음)으로 바꿨습니다.** 소리 분류 모델은 일상 소리에서 오경보가 시간당 수십~수백 회라 단독 알림에 쓸 수 없었습니다 ([11](11_VOICE_ASR_TRACK.md)).
- 파이4 실측: "도와주세요" 34/34, 처음 보는 문장 31/39(79%), 일상 소리 3시간 + 다른 녹음 87분에서 오경보 0회, 구간당 처리 평균 2.7초 (음성 팀 녹음 기준, 한 집).
- **한계**: "도와주세요" 외 문장은 약 70~90%, 어르신 목소리·다급한 발음·TV 속 대사는 아직 시험하지 못했습니다. 방열판 없는 파이4에서는 온도 제한이 걸렸습니다.
- 음성+영상을 같은 파이5에서 동시에 돌리는 시험은 파이5 도착 후에 합니다.

### 참고: 오경보 허용 수준을 정할 때

- 지금 방식의 음성 단독 오경보는 우리 녹음에서 일상 소리 3시간 + 87분에 0회입니다. 한 집·한 사람의 녹음이라 **다른 집, 다른 사람, TV 드라마에서는 달라질 수 있습니다.**
- **하루 몇 회까지 괜찮은지**는 아직 팀이 정하지 않았습니다 (시간당 1회는 하루 24회).
- TV 속 대사처럼 같은 말이 반복되면 "30초 안에 2회 이상 → 긴급" 규칙이 오경보를 낼 수 있어, 마이크 도착 후 횟수·시간을 실측해서 조정하기로 했습니다.

### 이벤트 JSON (v0.5)

[12 §2](12_TEAM_AGREEMENT_V05.md)에 항목 표가 있습니다.

```json
{
  "incident_id": "evt_20261120_031221_001",
  "source": "audio",
  "event_type": "help_request",
  "confidence": 0.74,
  "occurred_at": "2026-11-20T03:12:21.345+09:00",
  "repeat_in_30s": 1,
  "model": "whisper-tiny",
  "clip_file": "evt_20261120_031221_001.wav"
}
```

- 시각은 파이에 RTC가 없어서 **인터넷 동기화 후**의 값이어야 함 ([05](05_RASPBERRY_PI.md)).
- 11/03 초안의 `event_id`, `score`, `clip`, `speaker` 항목은 `urgent_service.py`(소리 분류 갈래)용이고, 새 서비스는 위 항목을 보냅니다.

## 3. 다른 파트와의 역할 경계

| 항목 | 현재 음성 파트의 입장 | 협의 필요 |
|---|---|---|
| **낙상 감지** | 음성은 "넘어졌어요", "도와주세요" 같은 **말소리 단어**를 잡는다. 쿵 충격음과 비명·신음은 보류(소리 분류 단독 알림은 오경보가 큼). 영상의 `fall`과 10초 안에 겹치면 "긴급" | 음성 `distress`·`impact` 단독을 "기록만"으로 낮출지 (제안) |
| **영상 `lying_long`** | 앱 파트는 단독 긴급에 찬성 | 이미지 파트가 몇 분 이상을 "오래"로 볼지 |
| **최종 장비** | 개발은 파이4, 최종은 파이5 (파이5 미도착). 파이4에서 구간당 2.7초 | 영상과 음성이 같은 파이5에 올라갈 때의 CPU 경쟁을 도착 후 함께 시험. 파이5는 H.264 하드웨어 인코더가 없어 영상 클립은 이벤트 때만 인코딩하는 방식을 권함 ([11 §8](11_VOICE_ASR_TRACK.md)) |
| **설치 장소** | 마이크 위치와 TV·가전 위치에 따라 오경보가 달라짐 | 시연 장소, 와이파이 환경 |
| **알림 연동** | [12](12_TEAM_AGREEMENT_V05.md)에 따름 | 영상 알림과 한 화면에 보여 줄지 (통합 판단 프로그램이 결정) |

## 4. 개인정보와 녹음 (꼭 지킬 것)

- **다른 사람의 목소리를 녹음할 때는 사전에 동의서를 받는다.** (AI Hub 데이터 구축 문서도 녹음 대상자의 허가와 동의서를 요구하는 절차를 설명한다.)
- **클립은 앱으로 보내지 않고 파이에만 저장한다** (11/06 합의). 보관 기간과 개수·용량 상한은 아직 정하지 않았다 (제안: 상한을 두고 오래된 클립 자동 삭제).
- **상시 녹음은 하지 않는다**: 파이는 최근 구간만 메모리에 들고 있고, 감지된 순간만 파일로 저장한다.
- 이 저장소에 **오디오, 모델 파일, 키, IP, 계정, 비밀번호, 와이파이 이름을 올리지 않는다.** 인식한 글자 파일(`*_windows.jsonl`)에는 대화 내용이 들어 있어 올리지 않는다.

## 6. 모델·데이터 공유 규칙

- **모델 파일(학습 결과)은 팀 안에서 공유 가능.** 단, 저장소에는 올리지 않고 팀 공유 폴더 등으로 전달 (`.gitignore`가 막고 있음).
- **AI Hub 데이터 원본은 재배포 금지.** 각자 AI Hub에서 신청해 받는다.
- 코랩 노트북과 스크립트는 [../code](../code)에 있고, 재현 순서는 [06](06_COLAB_RUNBOOK.md)과 [11 §10](11_VOICE_ASR_TRACK.md).
