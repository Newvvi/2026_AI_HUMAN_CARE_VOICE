# 15. 파이5 임시 확인 세션 계획 (파이4의 SD카드를 파이5에 잠깐 꽂아 확인)

> 이미지 파트가 파이5를 받으면 그쪽에서 쓰게 되므로, **파이5가 우리 손에 있는 1~2시간 동안** 가장 큰 미확인(파이5 속도, 모델 크기 결정, 열)을 실측하는 계획입니다. 파이5는 아직 도착하지 않았고, 아래는 **계획이며 실행 전**입니다. 파이5 수치는 [11 §8](11_VOICE_ASR_TRACK.md)의 추정입니다.

## 1. 해 볼 만한가

- **네, 1시간 이상 빌릴 수 있고 준비가 끝났다면 할 만합니다.** 모델 크기(tiny 상시 / base 상시 / small 보조)를 정하는 데 필요한 값이 대부분 파이5에서만 나오고, 도착한 뒤 이미지 파트와 같이 시험하기 전에 음성 쪽 숫자를 미리 알면 시간이 줄어듭니다.
- 1시간 미만이면 `--quick`(약 25분)만 하거나 건너뛰는 편이 낫습니다.
- 한계: 영상 프로그램이 이 SD에 없어서 **동시 실행은 이 세션에서 확인하지 못합니다.** 대신 CPU 코어 3개를 쓰는 부하(`stress-ng`)로 모의합니다 (영상이 실제로 얼마나 쓰는지는 모르므로 모의일 뿐입니다).

## 2. 같은 SD카드가 파이5에서 부팅되는가

- 공식 64비트 Raspberry Pi OS 이미지는 파이4용 `kernel8.img`와 파이5용 `kernel_2712.img`를 모두 담고 있어, 같은 SD카드로 파이4와 파이5 모두 부팅된다고 알려져 있습니다 (포럼 설명, [Raspberry Pi 문서](https://github.com/raspberrypi/documentation/pull/4195/files)가 두 커널 파일 이름과 기본 선택을 설명). 우리 SD가 공식 이미지에서 만들어졌는지는 **빌리기 전에 파이4에서 확인**합니다 (§3의 1).
- 두 커널은 **페이지 크기가 다릅니다**(파이5는 16K, 파이4는 4K). 일부 프로그램이 16K 페이지에서 오류를 낼 수 있습니다 (우리 패키지에서 나는지는 모름). 오류가 나면 SD의 `config.txt` 맨 아래에 아래를 추가해 파이5도 파이4 커널로 부팅합니다. 이 경우 속도가 약간 다를 수 있습니다 (확인 필요). SD의 boot 파티션은 Windows PC에서도 읽고 고칠 수 있습니다.
```
[pi5]
kernel=kernel8.img
```

## 3. 빌리기 전 준비 (파이4에서, 약 15분)

1. 파이5 커널 확인: `ls /boot/firmware/kernel_2712.img` (파일이 보이면 정상)
2. 부하 모의 도구: `sudo apt install -y stress-ng`
3. 세션 스크립트 설치: `~/voice/pi5_session.sh` (`code/voice_pi/`에서 복사)
4. 모델 캐시 확인: `ls ~/.cache/huggingface/hub | grep -i whisper` (tiny, base, small이 있어야 인터넷 없이도 동작)
5. 서비스 자동 시작이 꺼져 있는지: `systemctl is-enabled voice_service` (`disabled`여야 함)
6. 파일 확인: `ls ~/pi_bench ~/e1.m4a ~/e2.m4a ~/new3 ~/voice/soak.wav`
7. 정상 종료: `sudo shutdown -h now` 후 전원이 꺼진 뒤 SD를 뺀다

## 4. 파이5 쪽 준비물

- 파이5 본체와 **냉각**(액티브 쿨러나 팬 케이스, 이미지 파트가 쓰는 것). 냉각 없이 장시간 돌리지 않는다.
- **27W(5V 5A) USB-C 전원** 권장. 약한 전원이면 `get_throttled`에 저전압(`0x1`, 기록은 `0x10000`)이 찍힌다.
- 네트워크: SD에 와이파이 설정이 있어 자동 접속하지만 **IP가 바뀝니다.** 먼저 `ssh <계정>@<호스트 이름>.local`을 시도하고, 안 되면 공유기에서 IP를 확인.
- HAT(reSpeaker)는 이 세션에서 파이5에 장착하지 않는다.

## 5. 순서와 시간

| 단계 | 하는 일 | 시간 |
|---|---|---|
| 1 | 부팅, ssh 접속, `source ~/asr/bin/activate` | 10분 |
| 2 | `bash ~/voice/pi5_session.sh --dry-run` 으로 계획 확인 | 2분 |
| 3 | `bash ~/voice/pi5_session.sh --quick` (tiny/base, 짧은 부하·열) | 약 25분 |
| 3' | 시간이 되면 `bash ~/voice/pi5_session.sh` (small 포함 전체) | 약 60~75분 |
| 4 | `~/pi5_report.txt` 확인, 정리, 종료(`sudo shutdown -h now`), SD 반납 | 10분 |

스크립트가 0 장비 정보 → 1 구간당 처리 시간(스레드 2, 4) → 2 서비스 실시간 지연 → 3 새 문장 재현율(base 주 모델, 전체는 small 주 모델도) → 4 CPU 부하 모의 → 5 열·안정성 15분을 차례로 돌리고 결과를 `~/pi5_report.txt`에 모읍니다. 결과 파일에는 IP·계정이 없어 그대로 공유해도 됩니다.

## 6. 결과를 보고 정하는 것 (제안)

| 항목 | 파이4 측정 | 결정 규칙 (제안) |
|---|---|---|
| base 구간당 시간 (스레드 2) | 5.5초 | **3초 이하, 부하 중 4초 이하면 base를 주 모델 후보로** (새 문장 재현율 79%, tiny는 69%). 아니면 tiny 유지 |
| small 구간당 시간 (스레드 2, 4) | 18.8초 | **4초 이하**(스레드 4)면 small 주 모델도 가능(90%), 아니면 small은 재시도(보조)로만 |
| small 재시도 처리 시간 | 약 21초 | 이벤트 지연이 24초에서 얼마나 줄어드는지 (10초 안이면 긴급 판단에 유리) |
| 열 (15분, 기본 설정) | 방열판 없이 최고 82℃ | 냉각이 있을 때 `get_throttled`의 **지금** 비트가 없음 |
| 부하 중 지연 | (파이4는 모의 없음) | 코어 3개 부하에서도 첫 인식 지연이 3초대를 유지하는지 |

결과는 [11 §8](11_VOICE_ASR_TRACK.md)의 추정표를 실측으로 바꾸고 [EXPERIMENT_LOG](EXPERIMENT_LOG.md)에 행을 추가해 기록하며, 모델 크기 결정은 [02 D26](02_DECISIONS.md)을 갱신합니다.

## 7. 지킬 것

- 이미지 파트의 SD카드와 설정은 건드리지 않는다 (우리 SD만 사용).
- 전원이 켜진 채 SD를 빼지 않는다. 반납할 때는 원래 SD를 되돌려 놓는다.
- 보고서와 대화에 IP, 계정, 비밀번호를 붙이지 않는다.
- 영상과의 동시 실행은 **파이5 도착 후** 한 SD에 함께 설치해 시험한다 (이 세션은 모의 부하까지).
