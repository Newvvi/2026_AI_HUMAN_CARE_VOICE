# 12. 팀 데이터 협약안 v0.5 (2026-11-08)

> 음성, 영상, 앱 파트가 주고받는 메시지와 판단 규칙의 합의 내용입니다. v0.4(11/06)에서 달라진 점은 §6에 있습니다.
> 접속 정보(주소, 포트, 계정, 비밀번호)는 이 저장소에 올리지 않고 DM으로 전달합니다. 파트 이름은 역할로 적었습니다.
> 같은 내용이 팀 공유 문서(공통 사양서)에도 있고, 이 파일은 저장소용 사본입니다.

## 1. 통신 (확정)

- 라즈베리파이 로컬 MQTT 브로커(Mosquitto). 폰은 같은 와이파이(시연 때는 폰 핫스팟), **파이 → 폰 단방향**.
- 토픽: 음성 `home/alert/audio`, 영상 `home/alert/vision` → **통합 판단 프로그램**(앱 파트가 파이에 만듦) → `home/alert/fusion`, `home/status` → 앱. `home/feedback`은 없음.
- 브로커 설치: 앱 파트가 안내(11/07). **파이5가 아직 도착하지 않아서** 시험은 파이4에 직접 설치해서 하고, 파이5가 오면 같은 설정으로 옮긴다. 계정과 비밀번호는 코드에 쓰지 않고 설정 파일·환경변수로 둔다.
- 앱은 `fusion`과 `home/status`만 받는다. 클립은 앱으로 보내지 않고 파이에만 저장한다.

## 2. 메시지 형식 (음성·영상 공통)

| 필드 | 필수 | 예시 | 설명 |
|---|---|---|---|
| `source` | 필수 | `audio` / `vision` | 어느 파트인지 |
| `event_type` | 필수 | `help_request` | 음성: `help_request`(당분간 이것만), 영상: `fall`, `lying_long` |
| `confidence` | 필수 | `0.74` | 0~1. 음성은 인식한 글자의 확신도(참고용) |
| `occurred_at` | 필수 | `2026-11-20T03:12:21.345+09:00` | 발생 추정 시각 (Asia/Seoul, ISO 8601, 밀리초) |
| `incident_id` | 권장 | `evt_20261120_031221_001` | 없으면 통합 판단 프로그램이 만듦. 파이에 저장한 클립 파일 이름과 같게 |
| `repeat_in_30s` | 선택 (음성) | `1` | 직전 30초 안에 이미 인식된 횟수(참고용). 통합 판단 프로그램이 직접 세므로 읽지 않아도 됨 |
| `detected_at`, `device_id`, `location`, `model`, `clip_file` | 선택 | | 앱은 읽지 않음. 우리 기록·분석용 |

```json
{
  "incident_id": "evt_20261120_031221_001",
  "source": "audio",
  "event_type": "help_request",
  "confidence": 0.74,
  "occurred_at": "2026-11-20T03:12:21.345+09:00",
  "repeat_in_30s": 1,
  "model": "whisper-tiny",
  "clip_file": "evt_20261120_031221_001.wav"
}
```

## 3. 이벤트 이름

| source | event_type | 뜻 | 상태 |
|---|---|---|---|
| audio | `help_request` | 도움 요청 단어(도와주세요, 살려주세요, 사람 살려, 119 불러주세요 등). 말소리를 글자로 바꿔서 판정 | 사용 |
| audio | `distress` | 비명·신음 | 보류 (소리 분류 모델 단독 알림은 오경보가 커서) |
| audio | `impact` | 쿵 하는 충격음 | 보류 |
| vision | `fall` | 넘어짐 | 사용 |
| vision | `lying_long` | 오래 누워 있음 | 사용 |

## 4. 클립

- 음성: 감지 앞 10초 + 뒤 10초 WAV(약 640KB), **파이에만 저장**, 파일 이름은 `incident_id`와 같게. 영상 클립 길이는 이미지 파트가 정함.
- 통합 판단 프로그램은 받은 메시지 전부(원본 JSON + 수신 시각)를 기록 파일로 남기고, 공동 테스트 때 그 기록에 실제 위급/오경보를 표시해 재학습에 쓴다.
- 파이5는 H.264 하드웨어 인코더가 없어서(소프트웨어 인코딩에 코어 하나 정도, [11 §8](11_VOICE_ASR_TRACK.md)), 영상 클립은 프레임을 메모리에 쌓아 두었다가 이벤트가 났을 때만 인코딩하는 방식을 권한다.

## 5. 판단 규칙 (통합 판단 프로그램)

| 상황 | 단계 | 비고 |
|---|---|---|
| 영상 `fall`/`lying_long` + 음성 `help_request`가 10초 안에 | 긴급 | |
| 음성만 | 주의 | 음성 단독 오경보는 일상 소리 3시간 + 다른 녹음 87분에서 0회 (한 집 기준, [11](11_VOICE_ASR_TRACK.md)) |
| 영상만 | 주의 | |
| 영상 `lying_long`만 | 긴급 (제안) | 앱 파트 찬성. 몇 분 이상을 "오래"로 볼지 이미지 파트가 정하면 반영 |
| 음성 `distress`만 / `impact`만 | 기록만 (제안) | 앱 파트의 원래 규칙은 "distress만 → 주의". 음성은 현재 두 이벤트를 보내지 않음 |
| 음성 `help_request`가 30초 안에 2회 이상 | 긴급으로 올림 (앱 파트 동의) | TV 소리처럼 같은 말이 반복되면 긴급 오경보 가능 → 마이크 도착 후 실측해서 횟수·시간 조정 |
| 같은 사고 (이벤트 시각 차이 10초 이내) | 앱은 기존 알림만 업데이트 (예: "도움 요청 3회") | 1분 재알림 금지 규칙은 뺌. 주의 → 긴급처럼 등급이 오르면 다시 울림 |

`incident_id`는 보낸 그대로 기록하고, 음성과 영상이 한 사고로 묶이면 통합 판단 프로그램이 새 사고 번호를 만들어 두 ID를 같이 적는다.

## 6. v0.4(11/06) → v0.5(11/08)에서 달라진 점

- 음성 `help_request`의 정의: 소리 분류 모델이 아니라 **글자 인식(단어 인식)** 으로 판정 ([11](11_VOICE_ASR_TRACK.md)).
- 음성 메시지에 선택 항목 `repeat_in_30s` 추가.
- 앱 파트 11/07 답변 반영: 반복 감지 동의, 1분 재알림 금지 삭제(앱에서 기존 알림 업데이트), `lying_long` 단독 긴급 찬성, `incident_id` 기록 방식, 브로커는 파이4에 직접 설치.
- `distress`·`impact` 단독은 "기록만"으로 낮추자는 제안 추가.
- 파이5 도착 전이라 음성+영상 동시 실행 시험은 도착 후로 미룸.
